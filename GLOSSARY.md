# Glossary

**Incident**:
A physical problem in the field (broken equipment, road hazard) reported by a Technician and triaged by an Operator.

**Incident ID**:
A unique identifier generated by the client when a Technician first saves an Incident. It stays the same for the Incident's whole life, including offline.

**Technician**:
A field worker who reports Incidents using the mobile app.

**Operator**:
A back-office user who triages, assigns, manages and resolves Incidents using the web dashboard.

**Current User**:
The Technician or Operator the client is acting as, chosen from a fixed set of known users. There is no login.

**Category**:
The kind of Incident: Equipment, Road Hazard, Safety or Other.

**Severity**:
How urgent an Incident is: Low, Medium, High or Critical. Set by the Technician at report time.

**Status**:
Where an Incident is in its lifecycle: Open, In Progress or Resolved. Only an Operator changes it.

**Assignee**:
The Operator responsible for an Incident. An Incident with no Assignee is Unassigned; new Incidents start Unassigned.

**Resolution Note**:
The Operator's explanation of how an Incident was resolved.

**Activity Log**:
The ordered record of Status changes on an Incident.

**Sync State**:
Whether a Technician's local change to an Incident or one of its Photos has reached the server: Pending, Syncing, Failed or Synced. Separate from Status. Each Incident and each Photo has its own.

**Conflict**:
A queued Technician change that the server rejects because an Operator has already moved the Incident out of Open. The server's version wins and the change is marked Failed.

**Photo**:
An image attached to an Incident as evidence. An Incident has one to five.
